# Зеркалирование режима маржи — план и журнал (2026-09-12)

## Цель и границы

Фолловер копирует `CROSSED`/`ISOLATED` мастера. В `ISOLATED` объём остаётся
вычисленным из денежного риска до Stop; плечо ограничивается так, чтобы
начальный залог был не меньше двойного расчётного убытка до Stop. Существующий
запас до ликвидации остаётся отдельным условием. Stop не гарантирует цену
исполнения при гэпе или отказе биржи.

Работа не включает автоматическое изменение account-wide Multi-Assets режима
фолловера, ручное добавление `positionMargin`, изменение риск-процента или
mainnet-торговлю. Биржевой отказ переключить режим — запрет нового входа.

## План рефакторинга

1. **Авторитетное состояние.** Передавать `marginType` из полного и
   symbol-scoped master `positionRisk` в `PositionState`; не доверять одному
   WS-событию. У фолловера сохранять режим даже по flat-строкам; конфликт
   HEDGE-строк или неизвестное значение считать неизвестным.
2. **Цель и риск.** Проводить желаемый режим через `TargetPosition` и ключ
   desired-state revision. При неизвестном master-режиме запрещать новый
   риск. Для `ISOLATED` ограничить плечо `floor(entry /
   (2×|entry−stop|×(1+fee_buffer)))`, но не повышать плечо выше прочих
   ограничений. Если даже `1x` не даёт запаса — пропуск входа.
3. **План и журнал.** На плоском символе строить
   `SET_MARGIN_TYPE → SET_LEVERAGE → MARKET_OPEN` (или прямую зависимость
   входа от режима, если плечо уже совпало). Любая ненулевая позиция того
   же символа блокирует смену режима/рост; сокращение, закрытие и защита
   продолжаются; даже при таком блоке flat HEDGE-нога получает zero-target
   для отмены оставшихся bot-owned Stop/TP. Отсутствующий/FAILED/UNKNOWN
   предшественник блокирует зависимое увеличение. No-COID config POST
   журналируется до отправки; неизвестный исход и crash-window разрешаются
   signed `positionRisk`.
4. **После входа.** Повторно прочитать Aster `positionRisk`: фактический
   `marginType` должен совпасть; для `ISOLATED` `isolatedMargin` должен быть
   ≥ 2×Stop-loss по фактическим qty/entry и действующему Stop; ликвидация
   должна оставаться дальше Stop с прежним буфером. Нарушение — защитный
   flatten, а не молчаливое принятие позиции.
5. **Приёмка.** Узкие offline проверки только для DAG/отказа/boot resolver;
   полное доказательство — подписанный Aster Testnet: реальные оба
   перехода, реальные ордера/Stop, фактическая маржа и ликвидация, повторный
   reconcile без дубликата, разрешение UNKNOWN чтением биржи и финальный
   flat/0 orders. Общие testnet-аккаунты изолировать file lock; старый бот
   временно остановить и обязательно возобновить. Вернуть исходные
   position/margin/Multi-Assets режимы тестовых аккаунтов.

## Наблюдения Testnet

- Первый signed запуск: Aster отказал `-4168` при попытке `ISOLATED` на
  тестовом аккаунте с Multi-Assets. Сделок не было; бот возобновлён.
  Это конкретный биржевой precondition, не offline предположение.
- Для живого сценария на disposable testnet-аккаунтах добавлены signed
  GET/POST `/fapi/v3/multiAssetsMargin`: тест переходит в Single-Asset
  только когда нет ни позиций, ни открытых ордеров по всему аккаунту;
  затем восстанавливает исходный режим. Production coordinator этого не делает.
- Второй signed запуск (до расширения проверок): оба перехода режима,
  позиция/Stop и `isolatedMargin ≥ 2×` с ликвидацией дальше Stop —
  `1 passed in 87.09s`, финальная очистка/восстановление в `finally`.
  После этого усилены проверка `1x`-границы и live-проверки идемпотентности/
  boot UNKNOWN; их итог фиксируется ниже после повторного запуска.
- Финальный расширенный запуск той же подписанной кампании — `1 passed in
  103.73s`: `ISOLATED` реально получен из Aster `positionRisk`, плечо `15x`,
  `isolatedMargin=5.16828252` против требуемых `4.64544080`,
  `liquidationPrice=72389.14424060` против Stop `75024.70`; затем Aster
  подтвердил переход в `CROSSED`. Запись `SET_MARGIN_TYPE` в журнале
  предшествовала `MARKET_OPEN`; после искусственного перевода уже
  подтверждённой конфигурационной команды в `UNKNOWN` boot resolver
  подтвердил её новым signed `positionRisk`, без повторной записи режима.
  Два дополнительных reconcile не создали команд/входов. `finally` на
  `main/copyc1`: flat, zero open orders, исходные position/margin/Multi-Assets
  режимы возвращены; старый dev bot возобновлён (`SIGCONT`, процесс жив).

## Corrective к ревью — 2026-09-13

Пункт 3 исходного плана выше формулировал запрет роста для любой занятой
HEDGE-ноги слишком широко. Фактический и сохраняемый контракт: занятый
символ запрещает **смену** `marginType`; рост при уже совпадающем подтверждённом
режиме разрешён (подписанный HEDGE resize-тест это закрепляет). При несовпадении
или неизвестном режиме рост по-прежнему блокируется; сокращение и защита идут.
Для `ISOLATED` 2× collateral cap теперь применяется и перед ростом существующей
ноги: planner сначала снижает плечо, затем открывает добавочный объём. Если
даже `1x` не покрывает Stop-risk, рост не планируется. Offline регрессии
проверяют downshift → `MARKET_OPEN` DAG и конфликт мастерских HEDGE-режимов,
включая flat-строку. Текущий общий тестовый статус — в `ENGINE_TEST_STATUS`.
