## 3. Операционное восстановление (всё — тестнет)

Рецепт продления агента доказан на copyc2: `delAgent` → `approveAgent` на
новый signer → `GET /agent` 200 (expiry +365 дн, `canPerpTrade`) → импорт
кредов → signed-reads `/account|balance|positionRisk` 200.

| Аккаунт | Что сделано |
|---|---|
| `copyc2` | Новый signer через delAgent+approveAgent; main-ключ был в wallet.txt (`evm private key`). Баланс ~643 USDT |
| `main` | Старый кошелёк без main-ключа → **новый кошелёк**: faucet-claim (EIP-712 `ClaimTestnetToken`, chainId 56 — публичный POST `/bapi/futures/v1/public/future/faucet/claim`, ~1500 эквивалента), approveAgent, замена кредов в БД (main_key теперь хранится) |
| `copyc1`, `copyc3` | Тот же рецепт: новый кошелёк → faucet → approveAgent → замена кредов |
| `tg-8264892202` | Тот же рецепт; привязка `telegram_users` сохранена, Mini App-сессия работает |

Замечания: faucet возвращает transient `099050` (повтор через ~1 мин проходит);
`import-wallet` CLI иногда виснет на shutdown потока aiosqlite (коммит
успевает); для замены user_address нужен `import-wallet --wipe` либо ручная
чистка `credentials`/`agent_validations` (применён второй путь).

Дополнительная правка данных (не кода): `copyc2`/`copyc3`
`max_entry_deviation_pct` выровнены `0.01 → 1.0` (как у copyc1/tg-*); иначе
эти фолловеры пропускали ~100% сделок по гейту отклонения на волатильной
книге.

## 5. Кампания testnet_soak (3 прогона по 30 мин)

Гейт: `CT_TESTNET=1 CT_SOAK=1`, клон БД, 6 циклов + listenKey reconnect
(~27%), graceful restart (~45%), SIGKILL-recovery (~65%), финальный flat-аудит.

| Прогон | Итог |
|---|---|
| 1 | Таймаут входа фолловеров: copyc2/copyc3 — отклонение цены (гейт 1%), tg-*/copyc1 — «сигнал мастера устарел»; cleanup flat |
| 2 | Смерть на ордере мастера: `-4131 PERCENT_PRICE` |
| 3 | Цикл 1 полный (входы+стопы+закрытия у 3 фолловеров); смерть на grow-фазе — таймаут ожидания |

**Root cause — среда, не код.** Книга BTCUSDT-тестнета патологична: mark
~60 844 при стакане ~61 911 (1,75% расхождения внутри банда ±2% →
`PERCENT_PRICE`, `-4131`). Рыночные заявки в хлысты отклоняются с вероятностью
~30–50%; циклу нужно ~4 подряд удачных филла, шести циклам — ~24.
До фаз reconnect/restart/SIGKILL прогоны не доходили.

Измеренный факт о продукте: движок переживает -4131 штатно — команда
FAILED после ретрая, следующий свип перепланирует и конвергирует; «узкое
место» — синхронные ожидания самого скрипта (`_cycle timeout=60` захардкожен,
мастер-ордера без ретрая, `SYMBOL="BTCUSDT"` захардкожен через импорт).

Упрочнения скрипта (не сделано, код не трогали): `--symbol` (SOLUSDT-книга
здорова), ретрай -4131 как транзиента в `_submit_master_order`/ожиданиях,
`--timeout` для `_cycle`. Опционально продуктовое: таксономия -4131 как
retryable для MARKET_OPEN — отдельное решение.
